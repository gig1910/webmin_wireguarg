# Аналитика WireGuard — эксплуатация

## Хранение

- Существующий runtime-график продолжает часто обновляться; его JSONL-кэш ограничен одним часом по умолчанию.
- SQLite в `/var/webmin/wireguard/stats/analytics.sqlite3` хранит потребление с шагом **10 минут** и точные метки наблюдаемых событий. Срок хранения — `analytics_retention_days`, по умолчанию 365 дней.
- Идентификатор пира — SHA-256 **публичного** ключа, не IP или имя. Приватный ключ не записывается в аналитику. При отключении/удалении пира записи остаются. Повторное использование IP другим ключом создаёт отдельную историю.
- Учитываются приросты RX/TX по накопительным счётчикам. Сбросы пропускаются и отмечаются; небольшие приросты на границах 10 минут делятся пропорционально времени (оценочно).
- События: первое наблюдение, активность/отсутствие, появление/смена endpoint (IP:порт), новое рукопожатие, смена интерфейса, сброс счётчиков, пропуск измерений. Это не доказательство нового подключения или местоположения.

## Миграция

При первом обнаружении известного публичного ключа старые JSONL-файлы этого пира однократно импортируются в SQLite. Исходный файл в процессе миграции не удаляется, но дальше подчиняется сроку хранения краткосрочного кэша. **Сохраните копию старого каталога статистики до обновления.** Для пиров, удалённых до миграции и не имеющих сохранённого публичного ключа, установить соответствие по необратимому хэшу старого имени файла невозможно. Не объединяйте историю по имени или IP.

## Вкладка «Аналитика»

Фильтр по пиру, включая удалённые из конфигурации ключи, и времени. График полученного/переданного трафика, события endpoint и handshake. Границы произвольного интервала округляются до пересекающихся 10-минутных квантов. При обрезанном ответе интерфейс показывает предупреждение: максимум 20 000 квантов и 2 000 событий на запрос.

## Обслуживание

Доступно только ACL `manage` и требует CSRF-защиты. Операции: удалить данные ранее момента, удалить по отпечатку ключа, очистить все данные, `VACUUM`. Для удаления необходимо ввести `DELETE`; перед ним создаётся SQLite online backup (`stats/backups/`, сохраняются 5 копий). Удаление по времени сохраняет 10-минутный квант, пересекающий указанную границу. SQLite WAL-транзакции согласуют обслуживание с активным сборщиком. После полной очистки сборщик продолжит запись при следующем опросе.

Для резервирования работающей БД используйте штатный SQLite online backup: простая копия одного файла без WAL может оказаться неконсистентной.

## Prometheus

В настройках модуля включите экспорт, выберите группы `traffic`, `peer_state`, `handshake`, `events`, `collector`, интервал и целевой `.prom`-файл в одном из разрешённых каталогов: `/var/lib/node_exporter/textfile_collector/` или `/var/lib/prometheus/node-exporter/`. Каталог должен существовать. Файл заменяется атомарно; в метках используется только отпечаток публичного ключа, без endpoint, IP или приватных ключей. Хранимый объём трафика экспортируется как **gauge**, поскольку очистка БД может его уменьшить.

Требуется `/usr/bin/python3` со стандартным модулем `sqlite3`, установка Perl DBI не нужна. Настройки вступают в силу после перезапуска *только сборщика*, без перезапуска WireGuard. Проверки: `python3 tests/analytics-store-test.py` и `./tests/run-tests.sh`; состояние в `stats/health.json`, поле `analytics_error`.

## Где посмотреть историю в Webmin

**Сеть → WireGuard VPN → Аналитика** — сводная история всех пиров, включая удалённые из конфигурации. На странице отдельного интерфейса есть кнопка перехода к общей аналитике; в таблице пиров рядом с каждым именем есть ссылка **«История»**, сразу фильтрующая аналитику по SHA-256 публичного ключа. Такая же ссылка находится на странице редактирования пира. Настройки экспорта Prometheus и хранения находятся в конфигурации модуля Webmin.

После обновления исходников Webmin необходимо **переустановить собранный пакет**, а не только перезапустить сборщик: интерфейс и CGI-обработчики находятся в самом пакете.

## Контроль установленной версии

Под заголовком страниц «Интерфейсы», «Аналитика», интерфейса и пира отображаются **версия сборки, Git-коммит и время сборки (UTC)**. Скрипт сборки автоматически присваивает новый номер каждому пакету, имя `.wbm.gz` теперь содержит этот номер. Если вкладка «Аналитика» не появилась, сверьте показанную версию с именем установленного пакета.
